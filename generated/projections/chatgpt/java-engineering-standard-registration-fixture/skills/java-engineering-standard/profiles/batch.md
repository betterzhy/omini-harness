# 批处理 Profile

- Profile Id: `batch`
- 规范版本: `0.4.0`
- 推荐基线: `java21-maven3`
- 兼容基线: `java21-maven3`、`java21-spring35-maven3`
- 模式: 主 Profile
- 适用对象：大批量、长时间、可分片且需要中断恢复的数据处理任务。

本文件只增加 Batch 的约束；通用规则以 [Java 开发规范](../JAVA-DEVELOPMENT-STANDARD.md) 为准。

| Id | 增量规则 |
| --- | --- |
| BAT-001 | 每次运行必须有稳定批次 Id、任务版本、Owner、输入范围和触发来源。 |
| BAT-002 | 输入必须形成不可变快照或可重建的高水位边界，禁止重跑时无声读取不同数据。 |
| BAT-003 | 长任务必须持久化 Checkpoint，记录已完成范围、版本和校验身份。 |
| BAT-004 | 分片键必须稳定、互斥且覆盖完整输入；重新分片必须防止遗漏与重复。 |
| BAT-005 | 重跑必须声明从头、从 Checkpoint 或仅失败项，并保证副作用幂等。 |
| BAT-006 | 重复消费必须通过业务键、版本或 Inbox 等机制识别，禁止只依赖进程内集合。 |
| BAT-007 | 输出必须与输入数量、金额或业务总量对账，并保留差异明细和处置状态。 |
| BAT-008 | 部分失败必须区分可重试、永久拒绝和人工处理；禁止吞掉失败继续报告全量成功。 |
| BAT-009 | 上游和下游之间必须有背压、速率限制和积压指标，禁止无界队列。 |
| BAT-010 | 必须固定线程、连接、内存、磁盘和单批大小上限，并在代表性数据量上验证。 |
| BAT-011 | 并行处理必须证明分片独立性；共享聚合或有序处理不得盲目并行。 |
| BAT-012 | 批次必须记录开始、结束、Checkpoint、版本、统计、错误、重试和操作人等审计信息。 |
| BAT-013 | 原始输入、中间结果、错误明细和审计记录必须分别定义保留、加密和删除策略。 |
| BAT-014 | 必须测试进程终止、节点丢失、重复启动、Checkpoint 损坏和下游不可用后的恢复。 |
| BAT-015 | 禁止把进程退出成功直接等同于业务批次成功；业务成功必须由对账与验收条件裁决。 |
