# 微服务 Profile

- Profile Id: `microservice`
- 规范版本: `0.4.0`
- 推荐基线: `java21-spring35-maven3`
- 兼容基线: `java21-maven3`、`java21-spring35-maven3`
- 模式: 主 Profile
- 适用对象：具备独立部署、演进、隔离或扩缩容证据的服务。

本文件只增加 Microservice 的分布式约束；通用规则以 [Java 开发规范](../JAVA-DEVELOPMENT-STANDARD.md) 为准。

| Id | 增量规则 |
| --- | --- |
| MS-001 | 拆分必须基于独立演进、扩缩容、故障隔离、合规或组织 Owner 证据；禁止以团队偏好或代码量为理由。 |
| MS-002 | 每个服务必须拥有并独立迁移自己的可写数据，禁止跨服务直接写表或共享 Repository。 |
| MS-003 | 同步与异步网络边界必须有版本化 Contract、Owner、兼容窗口和消费者清单。 |
| MS-004 | 每条同步调用链必须有端到端超时预算，子调用超时必须小于剩余预算。 |
| MS-005 | 重试只允许用于明确瞬时且幂等的失败，必须有限次、退避、抖动并受总截止时间约束。 |
| MS-006 | 熔断、隔离舱和并发上限必须基于依赖故障模式配置，禁止用默认值冒充容量设计。 |
| MS-007 | 所有副作用入口必须定义幂等键、作用域、保留期以及同键不同载荷冲突语义。 |
| MS-008 | 业务事实与出站事件必须通过 Outbox 或等价原子机制衔接。 |
| MS-009 | 消费者必须通过 Inbox 或等价机制处理至少一次投递、重复和重放。 |
| MS-010 | Contract 演进必须先扩展后收缩，并执行提供方/消费者兼容性测试。 |
| MS-011 | 禁止依赖全局消息顺序；需要顺序时必须声明分区键、乱序窗口和恢复策略。 |
| MS-012 | 服务必须传播 Trace、Correlation、认证和租户上下文，同时防止伪造和敏感泄露。 |
| MS-013 | 必须定义面向用户结果的 SLI/SLO，并为延迟、错误、饱和、积压和依赖故障建立告警。 |
| MS-014 | 发布必须支持可观察的灰度或分阶段放量，定义停止条件和兼容的回滚路径。 |
| MS-015 | 回滚必须覆盖代码、配置、Contract、消息和 Schema；不能回滚时必须有前滚修复方案。 |
| MS-016 | 必须定期演练实例丢失、区域/依赖故障、消息积压、数据恢复和流量切换。 |
| MS-017 | 服务目录必须记录 Owner、值班、Contract、数据、依赖、SLO、Runbook 和生命周期状态。 |
| MS-018 | 新服务上线前必须证明独立构建、测试、部署、观测、恢复和退役能力，缺失任一项不得拆分。 |
| MS-019 | 从同 JVM 模块拆为独立进程只改变 Transport 和运行隔离；Fact Owner、Contract、状态解释、数据写权和恢复责任必须显式迁移或保持不变。 |
| MS-020 | 服务内部仍应按业务 Owner 组织模块；禁止因已经是微服务就退化为全局 Controller/Service/Repository 技术层。 |
